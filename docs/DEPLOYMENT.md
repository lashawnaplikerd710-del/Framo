# 部署与运维设计

## 桌面分发

安装构建使用显式运行目录、音色目录、许可证目录和NSIS输入，按允许清单组织产物。不能把开发者的工作目录整体压成用户安装包。安装型配置应使用相对资源路径、独立UserData和干净的初始任务状态。

发行必须留存安装文件SHA256、构建版本、输入模块清单、第三方声明、安装／启动／升级／卸载验证。当前文档快照没有重新执行此构建。

## 网关接入

模型密钥保留在提供方环境，桌面用户使用自己的访问码。Cloudflare侧负责鉴权、允许模型、每日单位、累计次数和并发限制；提供方需要自行管理域名、Secrets和平台用量。

发放权限时区分：

| 字段 | 含义 |
|---|---|
| expires_at | 访问有效截止时间 |
| daily_units | 每个UTC日的模型加权请求单位，不是人民币或成品数 |
| max_requests | 累计模型请求上限，不随每天重置 |
| max_concurrent | 该用户并发模型请求上限 |
| enabled／models | 是否启用及可调用模型 |

同一用户ID的续期或换码不会自动清零累计次数。一个剪辑任务可以多次调用网关；一天50次网关请求不等于一天能做50条视频。

## 可恢复请求

请求编号、用户和摘要绑定，完成结果在保留期内可查询，不应重复调用上游。记录和最多约1MiB的生成结果按策略保留24小时；超大结果、上游断流或平台中止可能只保留不确定状态。真实环境仍需检查服务部署、平台限额和日志设置。

## 运维监控

分别记录鉴权拒绝、额度拒绝、连接／响应超时、模型格式不合格、编译失败、资源缺失、渲染失败和要求不符合。日志仅使用脱敏请求编号、阶段、模型标识、时长和结果；不得公开原始用户内容或访问码。

发布和回退前确认运行任务；旧任务有版本绑定，不允许仅修改版本号绕过恢复限制。桌面默认队列与临时批次监督器的并发策略必须分开记录。

## 对用户承诺的边界

网关健康检查、权限状态检查、模型响应和完整视频生成是不同验收层。提供方网络成功不等于所有用户网络可达，离线单测也不等于线上授权通过。
