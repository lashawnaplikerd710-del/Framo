# Framo 产品需求文档

文档版本：docs-2026.10.20。产品形态：Windows 桌面软件；商业方式：核心源码私有、独立访问码接入模型服务。当前能力与待完成需求分列，本文不代表所有要求已验收。

## 1. 用户和问题

核心用户是需要持续制作电商视频的个人卖家、跨境运营和小型内容团队。用户已经持有商品素材，希望减少逐条选段、重写口播、加字幕、编排元素和重复导出的操作。

典型困难包括素材较多、语言不同、原口播被切断、同批成品开头重复、长任务看不出进展，以及失败后不知道如何继续。产品以“输入要求与素材，输出可检查的视频及过程记录”为主要任务。

## 2. 产品目标

1. 把素材分析、语义规划、资源编排和渲染连接成可执行的桌面流程。
2. 同时支持需要新口播的电商内容和保留原口播的长视频混剪。
3. 对素材来源、时长和输出技术完整性进行程序校验，保留失败原因与检查点。
4. 为批量任务提供独立输出和可追踪状态，避免把排队误解为卡死。

不承诺平台原创认定、销量提升、所有网络稳定可达、任意第三方编辑器效果完全复现，或所有任务在任何异常下都能无人干预完成。

## 3. 主要用户故事

| 编号 | 用户故事 | 可检查结果 |
|---|---|---|
| US-01 | 运营导入本地商品视频，生成日本区或美国区成片 | 输出语言、配音策略、字幕和文件符合当前任务设置 |
| US-02 | 国内卖家通过自定义要求生成中文口播 | 目标语言为中文，并使用中文音色；不能只选择中文音色却保留日语任务目标 |
| US-03 | 创作者将多条原声素材混剪为3分钟长视频 | 保留原声音轨、已有字幕；不生成新配音或字幕；选段有真实来源 |
| US-04 | 同批制作7条，尽量使用不同开头 | 明确批次要求后，在足够多不同内容来源下分配不同开头；不足须说明 |
| US-05 | 任务失败后查看原因并恢复 | 保留事件与产物；鉴权、网络、资源和文案问题可区分 |
| US-06 | 接收安装程序并开始使用 | 独立安装、填写自己的访问码、不携带提供者任务历史 |

## 4. 功能需求和验收

| 编号 | 需求 | 当前实现／验收标准 |
|---|---|---|
| FR-01 P0 | 本地素材导入 | 最多20条；每条最长420秒；检查媒体信息和文件指纹 |
| FR-02 P0 | 模式选择 | 界面提供日本区、美国区、自定义、长视频、长视频无口播 |
| FR-03 P0 | 剪辑要求解析 | 生成结构化开关和引用依据；无关引文不得覆盖其他类别，当前有已知缺陷 KI-01 |
| FR-04 P0 | 原声长视频开头锁定 | 一条合格来源从零开始，连续至少40秒；句末延长受目标总长限制；编译器重查 |
| FR-05 P0 | 原声语义混剪 | 按完整语句、因果、问答和动作分组；同源区间不得重复，不能用重复片段凑时长 |
| FR-06 P0 | 模型规划与编译 | 只能引用已登记素材／语义单元；拒绝编造来源、非法时间和不合格计划 |
| FR-07 P0 | MP4交付 | 检查文件存在、画幅、帧数／时长、应有音轨和完整解码；技术通过不替代创意验收 |
| FR-08 P0 | 状态与恢复 | 阶段事件、失败原因、检查点、取消和恢复；恢复前校验素材及运行时绑定 |
| FR-09 P1 | 批量生产 | 最多15条独立输出，每条状态独立；界面常规队列默认一条执行 |
| FR-10 P1 | 配音与音色 | 本地目录69种音色，其中中文男女各5种；需要按音色条款保存署名 |
| FR-11 P1 | 视觉与声音元素 | 按要求安排转场、贴纸、文字动效、特效和音效；原声混剪装饰合计最多100次 |
| FR-12 P1 | 批次开头多样性 | 明确批次不同开头要求时按编号分配；文件内容哈希去除完全重复来源 |
| FR-13 P1 | 有声预览与目录 | 提供软件内预览、成品入口和目录设置；预览兼容性仍需目标电脑验证 |
| FR-14 P1 | 网关权限 | 到期、每日加权单位、累计请求上限和并发控制分开校验 |

## 5. 时长和资源约束

长视频最多600秒。普通长视频规划最多40个镜头、每段最多60秒；原声语义混剪最多160个完整单元。前四十秒规则只对带有对应策略的新建原声长视频任务生效，旧任务按创建时契约恢复。

贴纸目录条目、音色数量和动效预设数量都属于可用资源清单，不构成每条视频必须全部调用的要求。用户明确要求某类元素后，生成后的实际轨道应接受要求核对，不能仅依赖模型开关。

## 6. 交互流程

安装并配置访问码 → 添加素材 → 选择模式和时长 → 设置数量、音色及剪辑要求 → 创建任务 → 查看阶段进度 → 预览MP4 → 打开或更改成品目录。真实缺少资源、授权失效或无法通过的计划进入“需要处理／待补资源”，展示原因与下一步。

## 7. 非功能需求

- 可观察性：渲染反馈基于FFmpeg实际进度，阶段百分比不能冒充整批百分比。
- 可恢复性：产物保存哈希和修订号；版本变化不能直接忽略绑定继续执行。
- 数据边界：视频本地处理；模型所需文本与抽样画面仍会离开设备，须说明。
- 成本控制：调用次数、Token停止阈值与网关额度有界；不承诺无限重试。
- 兼容性：安装器目标Windows 10 22H2／Windows 11 64位；目标电脑仍须独立验证。
- 可维护性：发布快照须统一源码、运行模块、安装版本和文件指纹，当前尚未统一。

## 8. 验收指标

分别统计：提交数、生成MP4数、技术合格数、全部指令满足数、人工视听合格数。记录端到端耗时、阶段耗时、模型调用数、已报告Token、恢复次数与需要人工处理的次数。网关计费单位与供应商实际费用分开。

现有小样本不作为总体成功率、平均耗时或用户规模证明。最新七条的“生成7条”和“四类元素轨道存在6条”应同时公开，详见[评估](EVALUATION.md)。

## 9. 发布门槛

P0：解决 KI-01、统一版本快照；完成同输入回归和全流程验收。P1：安装包在独立环境验证，复核素材与音色条款；创建具有校验值的Release。文档仓库可先发布，但不得宣称上述发布门槛已经全部通过。
